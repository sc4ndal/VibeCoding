# PRD — 2단계: 재료 기반 레시피 생성

## 1. 개요 / 목표
1단계에서 인식된(또는 사용자가 수정한) 식재료 목록을 입력으로 받아, OpenRouter API의 텍스트 생성 모델을 호출해 해당 재료를 활용한 레시피를 생성하고 사용자에게 보여준다.

- 사용 모델: `nvidia/nemotron-3-ultra-550b-a55b:free` (환경변수 `RECIPE_MODEL`로 관리)
- 이번 단계의 성공 기준: 재료 목록을 기반으로 실행 가능한(제목/재료/조리순서가 포함된) 레시피를 화면에서 확인할 수 있다.

## 2. 사용자 스토리
- 사용자로서, 인식된 재료로 무엇을 만들 수 있는지 추천받고 싶다.
- 사용자로서, 인식이 잘못된 재료가 있다면 삭제하거나 재료를 직접 추가한 뒤 레시피를 요청하고 싶다.
- 사용자로서, 레시피의 조리 단계를 순서대로 명확하게 확인하고 싶다.

## 3. 기능 요구사항

### 3.1 프론트엔드 (React)
- 1단계 결과 화면에서 재료 목록 편집 기능
  - 인식된 재료 태그 삭제 가능
  - 재료 직접 추가(텍스트 입력) 가능
- "레시피 추천받기" 버튼
  - 클릭 시 현재 재료 목록을 백엔드로 전송
  - 요청 중 로딩(스켈레톤 UI) 표시
- 레시피 결과 화면
  - 레시피 제목, 사용 재료, 조리 순서(단계별 리스트), 예상 조리 시간 표시
  - 모델 응답 파싱 실패 시 원문 텍스트를 그대로 표시하는 폴백 UI

### 3.2 백엔드 (Node.js + Express)
- `POST /api/recipe/generate`
  - 요청 본문:
    ```json
    {
      "ingredients": ["계란", "우유", "양파", "당근", "대파"]
    }
    ```
  - 처리 흐름:
    1. 재료 배열 유효성 검증 (빈 배열 방지)
    2. 프롬프트 구성
       - system 프롬프트: "당신은 한국어로 답변하는 요리 어시스턴트입니다. 주어진 재료를 최대한 활용하고, 추가로 필요한 재료는 최소화한 레시피를 아래 JSON 형식으로만 응답하세요: {title, usedIngredients, extraIngredients, steps, estimatedTimeMinutes}"
       - user 메시지: 재료 목록 전달
    3. OpenRouter Chat Completions API 호출 (model: `process.env.RECIPE_MODEL`)
    4. 응답 텍스트를 JSON으로 파싱
  - 응답 예시:
    ```json
    {
      "success": true,
      "recipe": {
        "title": "양파 계란볶음",
        "usedIngredients": ["계란", "양파", "대파"],
        "extraIngredients": ["소금", "식용유"],
        "steps": [
          "양파와 대파를 잘게 썬다.",
          "팬에 식용유를 두르고 양파를 볶는다.",
          "계란을 풀어 넣고 함께 볶는다.",
          "소금으로 간을 맞춘다."
        ],
        "estimatedTimeMinutes": 15
      }
    }
    ```
  - 파싱 실패 시 응답:
    ```json
    {
      "success": true,
      "recipe": null,
      "rawText": "모델이 반환한 원문 텍스트"
    }
    ```

## 4. 비기능 요구사항
- 프롬프트에 "한국어로만 응답", "JSON 형식 준수" 등 명확한 지침을 포함하여 파싱 실패율 최소화
- OpenRouter 무료 모델 rate limit/지연 대응: 429 시 재시도 안내, 응답 타임아웃 30초
- 동일 재료 목록에 대해 재요청 시 매번 새로운 레시피가 생성될 수 있음을 사용자에게 안내(모델의 비결정적 특성)

## 5. 데이터 흐름 요약
```
[React] 재료 목록 확인/수정
   → [Express] POST /api/recipe/generate (재료 배열)
   → OpenRouter Chat Completions (RECIPE_MODEL, 재료 기반 프롬프트)
   → 응답 파싱 → 레시피 객체 반환
   → [React] 레시피 상세 화면 렌더링
```

## 6. 제외 범위 (Out of Scope)
- 재료 인식 (1단계에서 다룸)
- 레시피 저장, 사용자 프로필 (3단계에서 다룸)
- 영양 정보 계산, 레시피 난이도 평가 등 부가 기능

## 7. 성공 지표
- 재료 목록 전송 → 레시피 표시까지 평균 응답 시간 15초 이내
- 모델 응답의 JSON 파싱 성공률 85% 이상
