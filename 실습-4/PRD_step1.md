# PRD — 1단계: 냉장고 사진 업로드 & 재료 인식

## 1. 개요 / 목표
사용자가 냉장고 내부 사진을 업로드하면, OpenRouter API의 비전(Vision) 모델을 호출하여 사진 속 식재료를 자동으로 인식하고 텍스트 목록으로 보여준다. 이 목록은 2단계(레시피 생성)의 입력값으로 사용된다.

- 사용 모델: `google/gemma-4-26b-a4b-it:free` (환경변수 `VISION_MODEL`로 관리)
- 이번 단계의 성공 기준: 사용자가 사진 한 장을 업로드했을 때, 합리적인 시간 내에 인식된 재료 리스트를 화면에서 확인할 수 있다.

## 2. 사용자 스토리
- 사용자로서, 냉장고 사진을 찍어 업로드하면 안에 어떤 재료가 있는지 자동으로 알고 싶다.
- 사용자로서, 인식이 잘못되었을 경우 무엇이 잘못 인식되었는지 알아채고 다시 시도하고 싶다.
- 사용자로서, 업로드 중/분석 중임을 명확히 알고 싶다(로딩 상태).
- 요리 레시피를 작성할 때, 난이도와 요리 소요 시간도 작성.

## 3. 기능 요구사항

### 3.1 프론트엔드 (React)
- 이미지 업로드 UI
  - 드래그 앤 드롭 및 파일 선택(클릭) 방식 모두 지원
  - 업로드 전 썸네일 미리보기 제공
  - 지원 포맷: JPG, PNG / 최대 용량: 5MB (초과 시 클라이언트에서 즉시 에러 안내)
- 분석 요청 및 상태 표시
  - "재료 분석하기" 버튼 클릭 시 백엔드에 이미지 전송
  - 분석 중 로딩 스피너/스켈레톤 UI 표시
  - 분석 완료 시 인식된 재료를 태그/리스트 형태로 표시
- 에러 처리 UX
  - 네트워크 오류, 모델 응답 실패, 파싱 실패 등 상황별 에러 메시지 표시
  - "다시 시도" 버튼 제공

### 3.2 백엔드 (Node.js + Express)
- `POST /api/vision/analyze`
  - 요청: multipart/form-data로 이미지 파일 수신 (또는 base64 인코딩된 data URL)
  - 처리 흐름:
    1. 이미지 유효성 검증 (포맷, 용량)
    2. 이미지를 base64 data URL로 인코딩 (OpenRouter 비전 모델은 이미지 URL 또는 base64 data URL을 메시지 콘텐츠로 받음)
    3. OpenRouter Chat Completions API(`/chat/completions`) 호출
       - model: `process.env.VISION_MODEL`
       - messages: system 프롬프트("당신은 냉장고 사진에서 식재료를 인식하는 어시스턴트입니다. 인식된 재료만 한국어 명사 리스트로 JSON 배열 형태로 응답하세요.") + user 메시지(이미지 첨부)
    4. 모델 응답에서 재료 배열 파싱 (JSON 파싱 실패 시 정규식/후처리로 재시도)
  - 응답 예시:
    ```json
    {
      "success": true,
      "ingredients": ["계란", "우유", "양파", "당근", "대파"]
    }
    ```
  - 에러 응답 예시:
    ```json
    {
      "success": false,
      "error": "MODEL_RESPONSE_PARSE_FAILED",
      "message": "재료 인식 결과를 해석하지 못했습니다. 다시 시도해주세요."
    }
    ```

### 3.3 이미지 저장
- 업로드된 냉장고 사진은 Supabase Storage 버킷(예: `fridge-images`)에 저장
- 저장된 이미지의 public/signed URL을 응답에 포함하여, 추후(3단계) 저장 레시피에 원본 이미지를 연결할 수 있도록 함
- 1단계에서는 로그인 없이도 사용 가능해야 하므로, 비로그인 사용자의 이미지는 임시 경로(예: `anonymous/{uuid}.jpg`)에 저장하고 일정 기간 후 정리(cleanup) 정책은 3단계 이후 검토

## 4. 비기능 요구사항
- OpenRouter 무료 모델은 rate limit이 있을 수 있으므로, 429 응답 시 사용자에게 "잠시 후 다시 시도해주세요" 안내 및 재시도 로직(1회 자동 재시도) 적용
- API 응답 타임아웃: 30초 초과 시 타임아웃 처리 및 에러 안내
- 업로드 이미지는 클라이언트/서버 양쪽에서 용량·포맷 검증 (보안: 실행 파일 등 비이미지 업로드 차단)

## 5. 데이터 흐름 요약
```
[React] 이미지 선택
   → [Express] POST /api/vision/analyze (이미지 업로드)
   → Supabase Storage 업로드 (이미지 URL 확보)
   → OpenRouter Chat Completions (VISION_MODEL, 이미지 포함 메시지)
   → 응답 파싱 → 재료 배열 반환
   → [React] 재료 리스트 렌더링
```

## 6. 제외 범위 (Out of Scope)
- 레시피 생성 (2단계에서 다룸)
- 사용자 로그인/프로필/레시피 저장 (3단계에서 다룸)
- 재료 인식 정확도 개선을 위한 별도 모델 파인튜닝

## 7. 성공 지표
- 이미지 업로드 → 재료 리스트 표시까지 평균 응답 시간 10초 이내
- 정상 케이스 기준 API 성공률(파싱 성공) 90% 이상
